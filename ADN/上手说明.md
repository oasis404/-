## 一句话说明

用**纯 Python 标准库**（不依赖 numpy/scipy）实现两种自适应降噪滤波器（LMS 和 RLS），  
处理真实的 WAV 音频文件，可以直接在 VS Code 里下断点逐行调试。

## 文件都是干什么的

| 文件                       | 作用                    | 重点看这里                                          |
| ------------------------ | --------------------- | ---------------------------------------------- |
| `main.py`                | 主入口，串起整个流程            | 顶部的配置参数（第 58–66 行），改参数就在这改                     |
| `noise_cancellation.py`  | 核心算法库                 | **重点**：`lms_filter`（180 行）、`rls_filter`（232 行） |

| `visualize.py`           | 画波形 / 能量对比图（需 matplotlib） | 可选，先不装也能跑                              |
| `spectrogram.py`         | **画频谱图（最推荐看效果）**        | 我加的，降噪过程看得最清楚                        |
| `audio.wav`              | 自带的干净音频（20 秒）         | 你可以换成自己的文件                                     |
| `audio1.wav`             | 短版音频（3 秒），跑得快         | 调试时推荐用这个                                       |

**算法核心只有两个函数**，都在 `noise_cancellation.py`：

```python
# LMS：w(n+1) = w(n) + μ·e(n)·x(n)      —— 简单、稳、但收敛慢
# RLS：w(n+1) = w(n) + g(n)·e(n)        —— 快、但容易数值发散
```

其余函数（`read_wav` / `write_wav`）是手写的 WAV 读写，没有用任何库，  
这本身也是学习点——你可以看到 RIFF/WAVE 头是怎么解析的。

## ⚠️ 坑 2：RLS 跑起来"像卡住了"（不是死机）

如果你在 Step 4（RLS）看着屏幕半天没动静——**它没卡，是在算**。

RLS 每个采样点要做 **32×32 矩阵运算**（约 1024 次浮点乘加），  
88 万个采样点就是 **约 9 亿次运算**，纯 Python 循环要 **2～3 分钟**。  
而中间不打印任何东西，所以看起来像死了。

**本机实测耗时**：

| 输入                | 采样点  | RLS 耗时   |
| ----------------- | ---- | -------- |
| `audio1.wav`（3 秒） | 13 万 | 约 25 秒   |
| `audio.wav`（20 秒） | 88 万 | 约 2.5 分钟 |

**我加了进度显示**，现在会实时刷：

```
Step 4: Applying RLS adaptive filter...
    Filter order: 32
    RLS processing 882000 samples, this takes a while...
    RLS:   0.0%  (0/882000)  RLS:   5.0%  (44100/882000)  ...
    RLS: 100.0%  done
```

**想快点的话，两个办法**：

1. **用 `audio1.wav` 调试**——把 `main.py` 第 53 行改成 `input_file = "audio1.wav"`，只要 25 秒。  
   这也是我推荐你做 VS Code 断点调试时用它的原因。
2. **调小滤波器阶数**——`FILTER_ORDER = 32` 改成 `8`，运算量直接降到 1/16。

> 顺带说：RLS 慢是**算法本身的特性**（O(N²)），不是代码写坏了。  
> 真实产品里这活儿是交给 DSP 芯片或 C 代码做的，不是在 Python 里跑。  
> 工业实现通常还会做**分块频域**（MDF）优化，把复杂度降下来。

## ⚠️ 坑 1：我修了一处 RLS 数值发散（重要）

**原始仓库的 RLS 算法在处理长音频时会数值发散**：  
`cleaned_RLS.wav` 全是 0，指标算出来是 `nan`。

**原因**：RLS 需要维护一个"逆相关矩阵 P"，它必须保持对称正定。  
跑 88 万个采样点时，浮点误差累积会让 P 失去正定性，权重爆炸 → NaN。

**我的修复**（改在 `noise_cancellation.py`，原文件已备份为 `noise_cancellation.py.orig`）：

1. 每轮更新后把 P 矩阵**重新对称化**；
2. 给 P 的对角线加一个很小的下限（`DIAG_LOAD = 1e-9`，"对角加载"），  
   防止 P 失去正定性；
3. 加了非有限值保护，万一出错会重置状态而不是一路崩下去。

**修复效果**（本机实测，20 秒音频）：

| 指标       | 修复前   | 修复后         |
| -------- | ----- | ----------- |
| RLS SNR  | `nan` | 9.15 dB     |
| RLS 噪声降低 | `nan` | 57.8%       |
| LMS 噪声降低 | 97.1% | 97.1%（未受影响） |

> 这是个真实的工程 bug，修复思路（对称化 + 对角加载）在工业界的 RLS 实现里也是标准做法。  
> 你可以在 VS Code 里对比 `noise_cancellation.py.orig` 看我改了什么，这本身就是个学习点。

## 进阶（想继续深入时看）

这个工程是"降噪（去噪）"，属于**麦克风端处理**。真正的蓝牙耳机还有另一类算法在**扬声器端**：

- **ANC 主动降噪**：耳机自己放一个"反相声波"抵消外界噪声（低频效果最好）
  - 看这个：`https://github.com/schnili/ANC-Implementation`（FxLMS / FxRLS，MIT 协议，含飞机座舱噪声样本，需 pyroomacoustics）
- **AEC 回声消除**：通话时消除自己外放声音被麦克风收进去的回声
  - 看这个：`https://github.com/xiph/speexdsp`（SpeexDSP，BSD 协议，工业级，很多蓝牙芯片方案里集成了它）
- **EQ / 虚拟低频**：耳机出厂音效算法（这个本工程改改滤波器就能模拟）
- **编解码**：SBC / AAC / LC3（蓝牙传输音频的压缩格式，LC3 是 LE Audio 的新标准）

**你手上那副弱水时砂耳机**：不能拿来跑 ANC 实验（量产耳机固件锁死、抓不到内部麦克风信号），  
但可以用本工程输出的音频**A/B 试听** EQ / 降噪效果，或者用它的麦克风录一段真实环境噪声，  
喂给 `process_noisy_audio.py` 当实验素材。
